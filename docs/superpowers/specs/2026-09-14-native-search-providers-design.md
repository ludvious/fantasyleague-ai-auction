# Native Web Search Providers Design

## Goal

Replace the Brave-only `search_news` backend inside `LlmClient` with a
config-driven, multi-provider native web search: `responses` (OpenCode Go,
OpenAI, any OpenAI Responses-compatible endpoint), `anthropic` (Messages API
server tool), and `brave` (legacy). The bidding loop (`chat/completions`
function calling) is untouched. Verified live against OpenCode Go during the
2026-09-14 spike; Anthropic and OpenAI shapes verified against official docs.

## Confirmed decisions

- Result format for native providers: model summary + `Fonti:` lines
  (`title — url`) extracted from citations. Brave keeps today's
  `title — url` list unchanged.
- `configs/llm.yaml` example moves entirely to OpenCode Go: bidding on
  `/chat/completions` (OpenAI format, e.g. `gpt-5.6-luna`), search on `/responses`
  with `gpt-5.6-luna`, single `OPENCODE_API_KEY`.
- Single shared `httpx.Client` per run; search requests use full URLs like
  today's Brave GET. No new files, no backend classes: provider dispatch is
  three branches inside `LlmClient.search_news` (chosen over a
  `SearchBackend` abstraction and over per-buyer search config).
- `count` (tool arg) is used only by the `brave` provider; native providers
  search once per call.
- Session header: one stable `x-opencode-session` per run, auto-generated by
  the wiring when not configured; sent to all endpoints (harmless for
  non-Go). Custom `User-Agent: fantasyleague-auction/0.1` on every request
  (Go rejects generic UAs with Cloudflare 403).
- `llm.brave` stays accepted as legacy when `llm.search` is absent, so
  version-1 sidecars (`checkpoint.llm.yaml`) and old configs keep working
  with no schema bump. Both present → validation error. Neither → search
  disabled (`search non disponibile`); the current "brave required" rule is
  relaxed.
- Literal `api_key` is rejected inside `llm.search` (and `llm.brave`), same
  security invariant as today; keys are read only from `os.environ` via
  `api_key_env` names.

## Config contract

```yaml
llm:
  base_url: "https://opencode.ai/zen/go/v1"
  api_key_env: "OPENCODE_API_KEY"
  model: "gpt-5.6-luna"
  headers:                    # optional, applied to every request
    x-opencode-session: "…"  # optional; auto per-run default if omitted
  search:                     # optional; replaces llm.brave
    provider: "responses"    # required: responses | anthropic | brave
    model: "gpt-5.6-luna"    # required for responses/anthropic
    base_url: "…"            # optional, per-provider default
    api_key_env: "…"         # optional, inherits llm.api_key_env
    max_output_tokens: 400   # optional, default 400
    headers: {}              # optional, merged over llm.headers
```

Provider defaults for `base_url`: `responses` inherits `llm.base_url`;
`anthropic` uses `https://api.anthropic.com`; `brave` uses
`https://api.search.brave.com/res/v1/web/search`.

## Provider behavior

Shared Italian prompt: the query plus an instruction to search recent news
(injuries, form, starting role) and summarize briefly.

| | responses | anthropic | brave |
|---|---|---|---|
| Request | `POST {base}/responses` `{model, input, tools:[{"type":"web_search"}], max_output_tokens}` | `POST {base}/v1/messages` `{model, max_tokens, messages, tools:[{"type":"web_search_20250305","name":"web_search","max_uses":1}]}` | today's GET, unchanged |
| Auth headers | `Authorization: Bearer` | `x-api-key` + `anthropic-version: 2023-06-01` | `X-Subscription-Token` |
| Response parse | `message` output item → text parts + `url_citation` annotations | `text` blocks + `web_search_result` blocks | unchanged |
| Output | summary + `Fonti:` list | summary + `Fonti:` list | `title — url` lines |

Error handling (unchanged invariant): missing/empty/placeholder key or any
HTTP/parse error → `search non disponibile` message string; search performed
but no text → `nessun risultato`. The bidder never crashes.

## Wiring (`main.py`)

`_make_llm_client` resolves `llm.search` (or legacy `llm.brave`, or `None`)
into one search dict, builds the httpx client with
`User-Agent` + `llm.headers` (+ auto session header) as client-wide defaults,
and passes the search dict to `LlmClient`, whose constructor replaces the two
`brave_*` parameters.

## Testing

- `tests/test_llm_client.py` (MockTransport): per-provider request shape
  (URL, body, auth headers, tools), response parsing to the summary+fonti
  format, key-missing and HTTP-error fallbacks.
- `tests/test_cli.py`: `llm.search` validation (enum, literal `api_key`
  rejected, `model` required, `headers` mapping), legacy `brave` alone valid,
  both → error, neither → valid, sidecar round-trip with `search`, resume of
  an old `brave` sidecar. Existing "brave required" tests are rewritten to
  the new contract.
